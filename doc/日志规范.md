# XPhoto 日志规范（V1）

## 1. 目标

日志需满足以下目标：

- 可追踪：能还原关键请求与状态切换路径。
- 可定位：错误日志包含足够上下文，便于快速定位问题。
- 可审计：关键输入参数与配置变更有记录。

## 2. 日志输出位置与命名

- 默认日志目录：`{root}/logs/`（默认 root 为 `~/.xphoto`，可通过 `config.toml` 的 `root` 配置变更）。
- 文件命名格式：`name_date_pid.log`。
- 服务名建议：`xphoto-service`。
- 示例：`xphoto-service_20260215_12345.log`。

说明：每个进程独立日志文件，避免多进程互相覆盖。

## 3. 日志级别规范

- `INFO`：关键流程开始/结束、状态切换、核心输入参数。
- `WARN`：可恢复异常、无效输入、降级处理。
- `ERROR`：不可忽略错误，必须包含操作名 + 上下文 + 原始错误。
- `DEBUG`：详细内部过程（如 SQL 逐条初始化），默认可关闭。

## 4. 必须记录的日志点

### 4.1 启动与运行配置

- 启动命令行参数（`std::env::args()`）
- 完整环境快照（至少覆盖 `HOME/USER/HOSTNAME/CONFIG_PATH/BIND_ADDR/DATABASE_URL/LOG_DIR/LOG_LEVEL` 和 scan 相关覆盖变量）
- 运行环境信息：服务版本、OS/ARCH/FAMILY、可执行文件路径、当前工作目录
- 配置来源与核心参数：`config_path`、`config_root`、监听地址、数据库 URL 与 sqlite 文件路径、日志目录、扫描并发/检查点/恢复参数、相册规则开关
- 数据库连接状态、schema 初始化结果

### 4.2 请求入口与出口

- 每个 RPC 入口记录关键参数（避免敏感信息）
- 请求完成记录结果摘要（如返回数量、分页参数）

### 4.3 状态切换

- 任务生命周期（pending -> running -> success/failed）
- 关键资源变更（新增 source、创建 album、删除/软删 photo）

### 4.4 错误处理

错误日志需包含：

- 操作名（operation）
- 上下文（context，建议 JSON）
- 原始错误（error）

参考范式：

```rust
std::fs::create_dir_all(&db_dir).map_err(|e| {
    let msg = format!(
        "Could not create database directory at {}: {}",
        db_dir.display(),
        e
    );
    error!("{}", msg);
    msg
})?;
```

## 5. 实施要求

- 使用结构化日志（字段化输出），至少包含：时间、级别、模块、文件行号、线程、message。
- 错误日志必须可直接定位到代码路径与业务上下文。
- 不记录敏感信息（后续如有 token/password 必须脱敏）。
