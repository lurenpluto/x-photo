# XPhoto V1 需求文件

## 1. 文档信息

- 项目名称：XPhoto（本地图片管理与展示系统）
- 版本：V1.0（首版）
- 文档目标：明确首版范围、功能、约束与可扩展设计，作为后续开发与验收依据
- 参考产品：Google 相册（本地化版本）

## 2. 项目目标与范围

### 2.1 项目目标

XPhoto 用于管理和展示本地图片资源，提供图片扫描入库、相册组织、检索查询和网页端展示能力。

### 2.2 V1 范围

V1 聚焦以下能力：

1. 基于本地文件系统（Linux/Windows 目录）进行图片管理。
2. Rust 软件管理服务实现图片扫描、元数据解析、数据库管理和 RPC 接口。
3. Web 前端实现照片流展示、选择操作、详情页、相册页。
4. 设计上预留后续扩展到分布式文件系统、智能检索、人脸/内容识别、图片编辑等。

### 2.3 非目标（V1 不强制）

- 跨设备自动同步
- 云端托管
- 完整 AI 识别能力（仅预留扩展点）
- 高级图像编辑能力（仅预留扩展点）

## 3. 总体架构要求

系统分为三层：

1. **存储抽象层**：统一访问不同文件系统的数据源。
2. **软件管理服务（Rust）**：负责扫描、建模、索引、查询、相册管理、RPC 服务。
3. **前端展示服务（Web）**：负责图片流展示、交互操作和信息编辑。

要求：

- 各层通过明确接口解耦，避免前端直接依赖具体文件系统。
- 存储层必须有可替换设计，以支持后续接入 DFS 或其他存储后端。

## 4. 存储系统需求

### 4.1 V1 支持

- 支持本地文件系统目录作为图片来源。
- 支持多目录、多来源配置（例如家庭照片目录、工作目录等）。

### 4.2 抽象接口要求（为后续扩展准备）

存储层需提供统一能力：

- 目录遍历与增量扫描（按路径、时间戳、文件签名等）
- 文件读取（元数据读取、缩略图读取）
- 文件操作（至少预留删除能力接口）
- 文件唯一标识获取（用于去重和稳定引用）

### 4.3 扩展目标

- 后续可接入 DFS / 对象存储等实现，不影响上层业务逻辑。

## 5. 软件管理服务需求（Rust）

### 5.1 核心职责

- 扫描并录入照片
- 解析与管理照片元信息
- 相册管理
- 检索查询
- 向前端提供 RPC 接口

### 5.2 照片录入与元数据处理

功能要求：

1. 支持扫描指定数据源（多目录、多来源）。
2. 解析图片基本信息：
   - EXIF（如拍摄时间、拍摄参数）
   - 文件名
   - 文件路径
   - 创建日期
   - 修改日期
   - 文件大小
3. 默认排序时间规则：
   - 第一优先级：拍摄时间
   - 第二优先级：创建日期
   - 第三优先级：修改日期
4. 支持照片备注信息的读写（通常由前端触发修改）。

### 5.3 相册系统

功能要求：

1. 相册可手动创建。
2. 相册可自动创建（基于目录命名规范，见 5.4）。
3. 一个照片可属于多个相册（多对多关系）。
4. 相册必须有可展示名称。
5. 相册支持维护：
   - 增加照片
   - 删除照片
   - 修改名称
   - 修改备注信息
6. 相册支持缩略图：
   - 默认使用第一张照片
   - 支持手动指定封面
7. 相册内部 ID 使用哈希机制，要求全局唯一且不重复。

### 5.4 目录命名规则驱动的自动建相册

场景示例：`2020.02.01.大沙河长廊.人才公园.流花山`

规则要求：

1. 对符合规范的目录，自动创建相册。
2. 从目录名中提取：
   - 日期：`2020.02.01`
   - 相册名：`大沙河长廊.人才公园.流花山`
3. 不符合规范的目录，不自动创建相册。
4. 目录匹配规范可扩展，支持后续新增范式。

### 5.5 检索系统

功能要求：

1. 根据照片信息进行查询（时间、名称、路径、备注、EXIF 等）。
2. 支持查询照片所属相册列表。
3. 设计上支持未来扩展：模糊检索、智能检索。

### 5.6 扩展元数据能力（预留）

数据库和服务需支持持续扩展以下维度：

- 图片内容标签
- 人脸信息
- 事件信息
- 地点信息

并支持在这些维度上进行检索和聚合。

### 5.7 图片编辑能力（预留）

后续支持：

- 文件级操作（如删除）
- 图像级编辑（如调色）
- 编辑后保存与版本策略（V1 可先定义接口，不要求完整实现）

### 5.8 RPC 接口

软件管理服务必须提供 RPC 接口给前端调用，至少覆盖：

- 照片分页查询
- 照片详情查询
- 照片备注更新
- 照片批量操作（删除、加入相册）
- 相册列表/详情查询
- 相册创建与编辑

## 6. 数据库需求

### 6.1 核心实体（建议）

- `photo`：照片基础信息与元信息
- `album`：相册信息
- `photo_album`：照片与相册关联关系（多对多）
- `source`：数据源（扫描根目录、来源类型）
- `photo_extra`（可选扩展）：存储可扩展分析结果（JSON/结构化表）

### 6.2 设计要求

- 支持大规模照片数据的分页与排序。
- 对常用查询字段建立索引（时间、路径、名称、相册关联等）。
- 兼顾结构化查询与扩展字段存储。
- 支持后续新增分析维度，不破坏已有模型。

## 7. 前端展示服务需求（Web）

### 7.1 照片栏

- 以时间日期分组的瀑布流展示全部照片。
- 按默认时间规则排序。
- 支持大数据量滚动性能优化（虚拟滚动/分段加载）。
- 点击缩略图进入照片详情页。

### 7.2 照片选中与批量操作

- 支持单选和多选。
- 选中后顶部出现操作栏。
- 首批操作包括：
  - 删除
  - 添加到相册

### 7.3 照片详情页

布局要求：

- 左侧展示照片
- 右侧展示详情信息

详情字段至少包括：

- 拍摄日期
- 拍摄参数（EXIF）
- 照片名称
- 文件路径
- 所属相册
- 文件大小
- 位置信息（如可解析）

### 7.4 相册栏

- 相册按创建时间排序展示。
- 卡片信息至少包含：缩略图 + 相册名。
- 点击进入相册详情后，按时间顺序展示相册内照片。
- 支持相册编辑：
  - 修改相册名
  - 增删相册内照片
  - 修改相册备注

说明：新增照片到相册通常在照片栏通过批量操作完成。

### 7.5 后续栏目（预留）

- 人物栏
- 地点栏
- 其他基于内容聚合的栏目

## 8. 非功能性要求

- **性能**：支持大规模照片库的可用检索与流畅滚动。
- **可扩展性**：存储层、元数据层、检索能力均可扩展。
- **可维护性**：模块边界清晰，接口稳定。
- **兼容性**：至少支持 Linux 与 Windows 目录结构。

## 9. 需求拆分建议（V1 实施优先级）

### P0（必须）

1. 本地文件系统多目录扫描与照片入库
2. 照片元数据解析（EXIF/文件属性）
3. 照片栏展示 + 详情页展示
4. 相册基础能力（手动创建、增删照片、封面设置）
5. 目录命名规则自动建相册（首批范式）
6. 基础检索与 RPC 接口打通

### P1（应有）

1. 照片多选与批量操作完整体验
2. 相册编辑完整能力（名称/备注/封面）
3. 检索性能优化与索引完善

### P2（预研/后续）

1. 智能检索与模糊检索增强
2. 人脸/内容/事件识别数据接入
3. 高级图片编辑能力
4. 非本地存储后端接入

## 10. 验收标准（V1）

满足以下条件可视为 V1 验收通过：

1. 能从多个本地目录完成照片扫描入库。
2. 能按默认时间规则在前端照片栏稳定展示。
3. 能查看照片详情并修改备注。
4. 能创建相册、维护相册照片关系、展示相册封面。
5. 目录命名符合规范时可自动创建相册，不符合不创建。
6. 能通过检索接口查询照片并返回所属相册信息。
7. 前后端通过 RPC 接口完成核心业务闭环。

## 11. 术语说明

- 照片默认时间：拍摄时间 > 创建日期 > 修改日期
- 自动建相册：按目录命名规则自动生成相册并归集照片
- 来源（Source）：一个可扫描的数据根路径及其配置
