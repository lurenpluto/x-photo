# X-Photo 快速开始与使用指南

本文覆盖从拉取代码、构建运行，到 Web 控制台核心操作与注意事项。

## 1. 环境准备

- Rust 工具链（包含 `cargo`）
- Python 3（用于启动 Web 静态文件服务）
- Git

建议先确认：

```bash
cargo --version
python3 --version
git --version
```

Windows 可使用 `python --version` 或 `py -3 --version`。

## 2. 拉取代码

```bash
git clone <your-repo-url> x_photo
cd x_photo
```

## 3. 一键启动（推荐）

项目根目录已提供跨平台脚本，会先构建 `service` 再启动后端与前端。

### Linux / macOS

```bash
./start.sh
```

停止：

```bash
./stop.sh
```

### Windows PowerShell

```powershell
.\start.ps1
```

停止：

```powershell
.\stop.ps1
```

### Windows CMD

```bat
start.bat
```

停止：

```bat
stop.bat
```

## 4. 默认地址与日志

- Web: `http://127.0.0.1:5174`
- API: `http://127.0.0.1:8080/rpc/v1`
- 服务标准输出日志：`.service.log`
- 服务错误日志：`.service.err.log`（Windows 脚本会写入）
- Web 标准输出日志：`.web.log`
- Web 错误日志：`.web.err.log`（Windows 脚本会写入）
- 进程 pid：`.service.pid`、`.web.pid`

可通过环境变量覆盖：

- `SERVICE_HOST` / `SERVICE_PORT`
- `WEB_HOST` / `WEB_PORT`

示例：

```bash
SERVICE_PORT=18080 WEB_PORT=15174 ./start.sh
```

## 5. 手动启动（可选）

当你希望分开调试时可用：

```bash
# 启动后端
cargo run --manifest-path service/Cargo.toml --bin service

# 另一个终端启动 Web
python3 -m http.server 5174 --bind 127.0.0.1 --directory web
```

## 6. 首次运行注意事项

- 默认运行根目录为 `~/.xphoto`（日志、数据库、默认配置都在这里）。
- 默认配置文件：`~/.xphoto/config.toml`，首次启动会自动生成。
- 默认仅监听本机 `127.0.0.1`；若需外网访问，请先补齐认证和安全策略。

### 6.1 标准配置模板（推荐）

仓库提供了完整模板：[`doc/config.example.toml`](doc/config.example.toml)。

- 模板包含当前 `config.toml` 支持的全部字段。
- 未显式配置时，系统会使用内置默认值。
- `preview_cache.max_bytes` 支持 `10GB` / `1000MB` / 字节数等写法。

可直接复制：

```bash
cp doc/config.example.toml ~/.xphoto/config.toml
```

Windows PowerShell：

```powershell
New-Item -ItemType Directory -Force -Path "$env:USERPROFILE\.xphoto" | Out-Null
Copy-Item ".\doc\config.example.toml" "$env:USERPROFILE\.xphoto\config.toml" -Force
```

## 7. Web 控制台核心操作

左侧主要标签：`照片`、`收藏`、`相册`、`设置`、`状态`。

### 7.1 照片

- 顶部支持关键词搜索 + 字段前缀搜索。
- 支持字段：`album:` `remark:` `exif:` `camera:` `lens:` `path:` `source:` `date:`。
- 支持分页、排序、时间范围筛选。
- 点击照片进入详情，可查看大图、EXIF、位置、相册归属、备注。

### 7.2 收藏

- 可在详情页点击星标收藏/取消收藏。
- 收藏页按时间线展示，支持分页和每页数量调整。
- 支持卡片内快速取消收藏。

### 7.3 相册

- 浏览相册列表，进入相册详情查看照片。
- 相册详情支持关键词/时间/排序筛选与分页。

### 7.4 设置

- 修改 API Base。
- 健康检查。
- Source 创建、刷新与触发扫描。

### 7.5 状态

- 查看任务总览、任务列表、任务详情。
- 支持取消任务与重试任务。

## 8. 搜索建议与快捷键

- 搜索框支持自定义建议面板（前缀、相册名、最近搜索）。
- 常用快捷键：
  - `/` 聚焦搜索框
  - `Esc` 返回上层或关闭当前详情
  - `←` / `→` 进行分页或详情切图
  - `+` / `-` / `0` 控制详情缩放

## 9. 常见问题排查

- 启动失败：优先检查 `cargo`、`python` 是否可用。
- 页面打不开：检查 `5174` 端口是否被占用。
- API 请求失败：检查后端是否启动，或 `设置` 页 API Base 是否正确。
- 图片不显示：确认 source 路径可访问，且文件权限正常。
- HEIC/HEIF 预览失败：后端会尝试生成 JPEG 预览缓存；请安装 `ImageMagick`（`magick`）或 `heif-convert`。
- 外部转换器查找顺序（默认）：`service 可执行文件同目录` -> `同目录/bin` -> `当前工作目录` -> `当前工作目录/bin` -> `PATH`。
- Windows 下会额外调用 `where magick` / `where heif-convert` 收集绝对路径；也支持显式环境变量覆盖：`PREVIEW_MAGICK_PATH`、`PREVIEW_HEIF_CONVERT_PATH`。
- 若刚安装了 ImageMagick 但服务仍提示找不到：请重开终端后再启动服务，或直接设置 `PREVIEW_MAGICK_PATH="D:\\Program Files\\ImageMagick-7.x\\magick.exe"`。
- PowerShell 中 `where` 是别名（`Where-Object`），请使用 `where.exe magick` 检查可执行路径。
- `start.ps1` 会自动尝试解析 `magick` 路径并注入 `PREVIEW_MAGICK_PATH` 后再启动服务。
- 可选配置（`config.toml` -> `[preview_cache]`）：`warmup_on_scan`（扫描时预热预览）、`warmup_concurrency`（预热并发数）。
- `preview_cache.max_bytes` 支持字节数或带单位字符串（如 `1048576000`、`1000MB`、`10GB`）；未配置时使用默认值。
- `preview_cache.ttl` 支持 `d/h/m/s`（如 `30d`）；若未设置则回退到 `ttl_hours`。
- `preview_cache.cleanup_interval` 支持 `d/h/m/s`（如 `10m`）；若未设置则回退到 `cleanup_interval_seconds`。
- 缩略图走后端 `/photos/{id}/thumb`，会缓存到 `preview_cache.dir/thumbs`；HEIC 预览会缓存到 `preview_cache.dir`。
- 缓存文件按 hash 分桶到多级子目录（例如 `ab/cd/...`），避免单目录文件过多导致性能下降。
- 可选编译特性：`cargo run --features heif_native --bin service`，启用 `libheif-rs` 内嵌解码优先（仍建议保留外部命令作为兜底）。
- 任务异常：到 `状态` 页查看错误详情并尝试重试。

## 10. 建议工作流

- 日常开发优先使用一键启动脚本。
- 变更后先看 `状态` 页与日志文件确认无报错。
- 涉及搜索、扫描、收藏的改动，建议至少跑一轮端到端手动回归。
