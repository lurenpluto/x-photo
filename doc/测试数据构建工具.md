# 测试数据构建工具

## 1. 目标

用于快速生成可扫描的本地照片目录结构，便于集成测试与手工联调。

## 2. 工具位置

- `service/src/bin/testdata_builder.rs`

## 3. 用法

在 `service` 目录执行：

```bash
cargo run --bin testdata_builder -- /tmp/xphoto_test_data
```

或使用策略参数：

```bash
cargo run --bin testdata_builder -- /tmp/xphoto_test_data --strategy family_us_weekends_small --year 2025 --seed 42 --clean --manifest /tmp/xphoto_test_data/manifest.json
```

当前支持策略：

- `sample`：
  - 最小样例数据，生成 1 张带 `DateTimeOriginal` 和 GPS 的照片。
  - 适合作为 CI、smoke test 和 EXIF/自动相册回归测试默认数据。
- `family_us_weekends_small`：
  - 取指定年份前 4 个周六，每次随机 3-6 张照片。
  - 适合快速验证批量目录规则和 manifest 结构。
- `family_us_weekends_medium`：
  - 取指定年份前 12 个周六，每次随机 8-16 张照片。
  - 适合本地功能回归和 UI 翻页/相册数量联调。
- `family_us_weekends_2025`：
  - 按周末生成 2025 年家庭出游相册目录（`YYYY.MM.DD.<景区名>`）
  - 每次随机 10-100 张照片
  - 拍摄时间随机分布在早上 6 点到晚上 12 点（23:59）
  - GPS 以美国常见景区为中心并做小范围抖动，保证同次出游的地理关联性

参数说明：

- `--strategy <name>`：选择生成策略，默认 `family_us_weekends_2025`。
- `--year <yyyy>`：指定年份，默认 `2025`。
- `--seed <n>`：指定随机种子，默认 `42`。
- `--jobs <n>`：并行生成线程数，`0` 表示自动按 CPU 核心数选择，默认 `0`。
- `--clean`：生成前删除输出目录，保证重复运行结果干净。
- `--manifest <path>`：写出 JSON manifest，包含策略、年份、种子、相册计数和每张照片的 EXIF/GPS/路径信息。

未知参数会直接报错退出，避免脚本拼写错误被静默忽略。

## 4. 可复用大数据集

大数据集建议生成一次后持续复用，不要每次测试都重建。仓库提供脚本：

```bash
./service/scripts/build_large_testdata.sh --output /data/xphoto_test_data --profile large --jobs 0
```

默认行为：

- 不删除已有输出目录。
- 如果某个场景的 manifest 已存在，并且对应场景目录存在，会跳过该场景。
- 单个场景内部通过 `rayon` 并行生成图片，`--jobs 0` 表示自动选择线程数。
- 所有 manifest 写入 `<output>/_manifests/`。
- 扫描时把 `<output>` 作为 source root 即可。

常用 profile：

- `sample`：只生成最小样例，适合确认工具链。
- `medium`：生成 sample + small/medium 数据，适合快速本地功能测试。
- `large`：生成多年份完整家庭周末数据，适合复用型手工压力测试。
- `stress`：生成更多年份完整数据，适合并行扫描和稳定性压力测试。

常用命令：

```bash
# 推荐先跑 medium，确认生成速度和磁盘空间
./service/scripts/build_large_testdata.sh --output /data/xphoto_test_data --profile medium --jobs 0

# 生成可复用大数据集；再次执行会跳过已存在场景
./service/scripts/build_large_testdata.sh --output /data/xphoto_test_data --profile large --jobs 0

# 如果生成时磁盘 IO 压力过大，可以降低并行度
./service/scripts/build_large_testdata.sh --output /data/xphoto_test_data --profile large --jobs 4

# 强制重建每个场景目录，但不删除整个 output
./service/scripts/build_large_testdata.sh --output /data/xphoto_test_data --profile large --jobs 0 --force

# 删除整个 output 后重建
./service/scripts/build_large_testdata.sh --output /data/xphoto_test_data --profile large --jobs 0 --clean
```

生成完成后，脚本会输出 summary 路径，例如：

```bash
/data/xphoto_test_data/_manifests/_summary_large.json
```

可以查看总照片数和场景分布：

```bash
python3 -m json.tool /data/xphoto_test_data/_manifests/_summary_large.json
```

如果已有后端服务在运行，可以用这批数据做一次 smoke：

```bash
BASE_URL=http://127.0.0.1:8080/rpc/v1 \
DATA_DIR=/data/xphoto_test_data \
TIMEOUT_SEC=1800 \
./service/scripts/smoke_test.sh
```

## 5. EXIF 写入说明

- 工具已在 Rust 代码内部写入 JPEG EXIF（`DateTimeOriginal` + GPS）。
- 不依赖外部 `exiftool`，可直接在本地和 CI 使用。
